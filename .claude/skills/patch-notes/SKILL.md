# 패치노트 (patch-notes)

세션에서 바뀐 것을 **사용하는 사람 시점**으로 정리해 링크 하나로 건넨다. 개발 용어·파일명·커밋 해시는 쓰지 않는다. 첫 사례: 2026-09-16 인사담당자용 안내(https://claude.ai/code/artifact/33957706-376b-432c-b659-9c0d73d9c43a).

## 1. 재료 모으기

1. `.claude/state.md` 세션 로그 + `docs/decision-log.md` 의 해당 기간 항목에서 **사용자가 체감하는 변화**만 추린다(리팩터링·테스트·문서 갱신은 뺀다).
2. 각 항목을 "어디서 · 무엇이 · 왜(문제였던 것)" 한 문장으로. 수치가 달라질 수 있는 변경은 반드시 넣는다.
3. 대상 확인: **사내(main)** 이면 제품명 없이 "HCROI 시뮬레이터", **공개판(product/commercial)** 이면 "Headroom". 브랜치 차이(`SITE_ENABLED`)에 따라 없는 화면(소개 페이지 등)은 해당 판에만 적는다.

## 2. 구성 (순서 고정)

| 절                  | 태그                   | 내용                                                                                                      |
| ------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------- |
| 머리                | —                      | 한 줄 제목(가장 큰 변화 1~2개) · 한 줄 요약 · 날짜 · 판(사내/공개판) · "데이터는 이 PC 브라우저에만 저장" |
| 핵심 기능 절(1~2개) | `더 정확해짐` / `추가` | 이번 업데이트의 주인공. PDF·리포트처럼 담당자 업무와 직결되는 것                                          |
| 화면 전반           | `달라진 것`            | 위치가 바뀐 컨트롤, 어두운 화면·휴대폰, 표기 변화                                                         |
| 수치 정확성         | `수정`                 | **잘못된 숫자가 나갈 수 있던 경우** — 무엇이 어떻게 잘못됐고 지금은 어떻게 되는지                         |
| 확인 부탁           | 카드                   | 담당자가 직접 해 볼 3~4가지(번호 목록 = 실제 순서) + "그대로인 것"(산식·등급·저장 방식)                   |

- 항목은 `굵은 이름 | 설명` 2열 목록. 이름 12자 이내, 설명 2문장 이내.
- 절은 최대 5개. 20개 넘게 바뀌었으면 묶어서 줄인다 — 전부 나열하지 않는다.
- 문장은 능동·현재형("~합니다"). "버그 수정" 대신 **무엇이 잘못됐었는지**를 쓴다("총 인건비가 절반만 들어가던 문제").
- 회사명·개인 이름·실제 수치 금지(공개 저장소 위생과 같은 규칙). 스크린샷은 가상 회사 샘플만.

## 3. 만들기

1. `template.html`(이 폴더)을 복사해 스크래치패드에 `hcroi-update-YYYY-MM.html`(공개판은 `headroom-update-YYYY-MM.html`)로 채운다. 토큰·서체·레이아웃은 템플릿 그대로(앱과 같은 흰 카드·파랑·고딕 톤, 라이트/다크 3중 정의).
2. `<title>` 은 "HCROI 시뮬레이터 N월 업데이트" / "Headroom N월 업데이트". 같은 달 두 번째면 "N월 업데이트 2".
3. Artifact 로 발행(`favicon` 📋, `description` 한 문장). 같은 달 갱신은 같은 파일 경로로 재발행해 링크를 유지한다. 발행 전 `artifact-design` 스킬 로드는 필수.
4. 사용자에게 링크 + 절 요약 3~5줄. 사용자가 공유 메뉴에서 담당자에게 전달한다.

## 4. 기록

- `.claude/state.md` 세션 로그에 "패치노트: <링크>" 한 줄.
- 공개판 패치노트는 `docs/plans/commercial-product.md` §11 진행 표에 날짜·링크 한 줄(있으면).
