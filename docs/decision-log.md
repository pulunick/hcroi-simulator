# 결정 이력

## 2026-09-09 — 기간 합산(월→분기→연간) · 엑셀 작성 편의

사용자 지적: "월로 넣으면 분기·연간이 자동으로 나와야 하고, 대시보드에서도 보여야 하는데 지금은 다 따로 움직인다."
9/8 기간 레코드 전환 때 합산 규칙을 두지 않은 것이 원인. 시연 전에 넣는다. 계획서 docs/plans/rollup-and-excel.md.

- **가장 잘게 넣은 값만 저장, 상위 기간은 읽을 때 계산**(`rollup.ts`, `workspace.effective`). 지표 미저장 원칙과 같은 선. 계산 레코드는 id `derived:…`, 편집·삭제 불가, "직접 입력으로 전환"으로 복사.
- **하위 기간이 모두 있을 때만** 만든다. 1~3분기만 있으면 연간을 만들지 않는다(추정 금지).
- **직접 입력 우선 + 불일치 경고.** 결산 조정으로 확정 연간이 분기 합계와 다른 일이 실제로 있어 직접 입력을 덮지 않고, 항목별 차이를 화면에 보인다.
- **차감 도출**: 직접 입력한 상위 기간이 있고 하위 기간이 하나만 비면 `상위 − 나머지`(사업보고서에 4분기 값이 없는 DART 관행). 검증 통과 시에만.
- **임직원 수 산정 방식(기간 평균/기말)의 역할 변경**: 표기용 메타데이터 → 합산 규칙(평균 반올림 / 마지막 값). 사슬을 올라갈 때는 반올림 전 평균을 써서 한 명씩 어긋나지 않게 한다.
- **월(M) 유형 추가.** 라벨 "2025년 3월", 짧게 "2025.03", 엑셀 "3월". 전기 = 전월. 문구 "전월 대비 · N개월 연속".
- **샘플에서 2025년 연간 레코드 제거** — 분기 4개에서 합산되는 것을 첫 화면이 보여 준다.
- **엑셀 `조직 정보` 시트에 금액 단위(원/천원/백만원)·손익 입력 방식(기간 실적/누계) 칸.** 결산서(천원·누계)를 그대로 붙여 넣게. 파일이 자기 단위를 운반하므로 1000배 오류가 섞이지 않는다. 내보내기는 원·기간 실적 고정.
- **템플릿 작성 편의**: 기간 드롭다운(19개), 연도·금액·인원 셀 유효성, 맨 끝 `검증` 열(수식: 필수 누락·세부 합계>총액·총원≠구분 합계·인건비>영업비용) + 붉은 조건부 서식, 머리글 메모, 시트 보호(비밀번호 없음, 입력 칸 300행만 열림).
  붙여넣기로 뚫리므로 안내용이고 규칙의 원본은 `validateRecord`. 검증 열은 가져오기가 읽지 않는다(수식 셀의 결과가 없으면 빈 칸으로 취급).
- 미룸: 가로형(열=기간) 템플릿은 담당자 결산 시트를 본 뒤. 월 추이 36점 라벨 밀집은 그대로.

## 2026-09-08 — 기간 레코드(분기·반기) · 금액 표시 단위 옵션 · 임직원 수 산정 기준 · 동종업계 비교 경로

### 전체 검수(코드 리뷰 7개 관점) 반영 — 2026-09-09

- **인원 산정 기준과 총원의 불일치 경로 제거**: 총원 = 기준을 적용한 구분 합계 라는 불변식을 레이아웃의 `$effect(workspace.applyHeadcountBasis)` 한 곳이 유지한다.
  엑셀 가져오기가 파일 기준으로 합계를 낸 뒤 기준을 바꾸거나(체크 해제) 기준만 바꾸고 다른 기간을 안 고치던 구멍이 닫혔다(`replaceRecords`·`setHeadcountBasis` 도 재계산).
- **화면과 가져오기의 검증 규칙 통일**: `validateRecord` = 입력값 + 세부 합계 ≤ 총액 + 인원 구분 0 이상 정수. 화면에서 만든 상태를 자기 엑셀이 거부하던 경우가 사라졌다.
- **대시보드 총 인건비**: 세부 내역이 있어도 총액은 편집 가능(세부 합계 ≤ 총액만 요구). "세부 내역 합계" 라는 잘못된 라벨을 `세부 합계 · 미분류` 로.
- **전기의 정의**: 목록상 앞 레코드가 아니라 **달력상 직전 기간**(2025 Q1 → 2024 Q4). 빠진 분기가 있으면 비교하지 않는다.
- **기간 추가 시 빈 레코드 금지**: 같은 유형이 없으면 최근 레코드를 기간 길이로 환산(연간→분기 ÷4)해 시작한다. 빈 레코드가 곧바로 기본 기간이 되어 "—" 만 보이던 문제.
- **저장값 이행**: 알 수 없는 기간 유형은 조용히 버리지 않고 개수를 경고로 알린다(`importJson` → `{ok, warning|error}`). load/importJson/되돌리기가 한 이행 함수를 쓴다.
- 금액 표기 규칙(칸/머리글/힌트)을 `format.ts` 로 모아 4개 화면의 복제를 제거. `formatAmount(0)` 이 "0.00천원" 이던 것 → "0천원". `NumberField` 는 전역 상태 대신 `hintUnit` prop.
- 라벨 상수화: 산정 방식 문구(`HEADCOUNT_METHOD_LABELS`) · 연도 범위(`YEAR_MIN/MAX`) · 기간 순번 문구(`periodText`) 를 한 곳에서. 조직 정보 시트 라벨 탐색 헬퍼 공유.
- 성능·중복: 대시보드 시리즈 지표 1회 계산, `mergeRecords` 기간 키 Map, 인건비/인원 구분 파서 공통화, 원본 불변에 `headcountBreakdown` 포함.

### 분기·반기 단위 — 기간 레코드로 전환

- `YearRecord` 를 **`PeriodRecord`** 로 바꿨다. 기간은 `{year, type: 'Y'|'H'|'Q', index}` 하나로 식별하고, 라벨·정렬·엑셀 텍스트·전기/전년 동기 계산은 `period.ts` 한 곳에서만 한다.
- **값은 그 기간의 실적 그대로** 저장·계산한다. 연율화(×N)는 넣지 않았다 — HCROI 는 같은 기간 비율이라 필요 없고, 금액 지표는 "각 기간 실적 기준"을 화면에 밝히는 쪽이 오해가 적다. 필요해지면 표시 계층 토글로 추가한다.
- **결산이 없는 분기는 반기 레코드**로 둔다(실무 확인: 분기 3개년 보유, 결산 없는 분기는 반기 실적만). 분기로 쪼개 추정하지 않는다.
- **추이는 한 유형만** 본다(분기·반기·연간을 한 줄에 섞지 않음). 기본은 조회 중인 기간의 유형, 유형이 둘 이상이면 셀렉트로 전환. 인사이트 문구도 유형별("전년/전기 대비", "N년/N기 연속").
- **전기**는 같은 유형의 바로 앞 기간(2025 Q1 → 2024 Q4). 반기·분기는 계절성이 있어 **전년 동기**도 함께 보여 준다.
- 정렬은 **끝 월 기준**이라 한 해의 분기·반기 뒤에 연간(합계)이 온다. 그래서 "최신 기간"은 연간이 우선된다(첫 화면이 연간으로 열린다).
- 기간 추가 시 **같은 유형의 최근 값**을 복사한다 — 분기를 추가하는데 연간 값을 복사하면 4배가 된다.
- 엑셀 `입력 데이터` 에 `기간` 열 추가(비우면 연간, `1분기`·`상반기`·`Q1`·`H1` 허용). 기간 열이 없는 옛 파일은 전부 연간. 병합은 기간 키로 매칭.
- localStorage 옛 형식(`years` 배열 + `year` 필드)은 load 때 자동 이행(키 `hcroi:workspace:v1` 유지). 새 저장 형식은 `records` + `baseId`.
- 샘플에 2025년 분기 4개를 추가했다(합계 = 연간, 하반기로 갈수록 커지는 계절성).

### 임직원 수 산정 기준

- 총 임직원 수에 **산정 기준**을 붙였다: 기간 평균(FTE)/기말 인원 + 계약직·파견·등기임원 포함 토글(기본 전부 제외).
- 기준은 **작업공간 단위로 하나**만 둔다(연도별 아님) — 연도마다 다르면 추이 비교가 무의미해진다.
- 연도별로 **인원 구분**(정규직·계약직·파견·등기임원)을 선택 입력할 수 있고, 입력한 연도의 총원은 기준을 적용한 합계로 자동 계산된다.
  구분을 안 쓰면 종전대로 총원을 직접 입력한다.
- 기간 평균/기말은 **표기용 메타데이터** — 계산에는 영향을 주지 않는다(사용자가 어느 쪽 숫자를 넣었는지 밝히는 용도).
- **엑셀이 기준을 함께 나른다**(`조직 정보` 시트 4행). 기준 없이 인원 구분만 오가면 다른 PC 에서 총원이 조용히 달라진다.
  기준 행이 없는 옛 파일은 현재 설정을 건드리지 않는다.
- 파견·도급을 총원에 넣으면 인건비에는 안 잡히는 경우가 많아 인당 지표가 낮아진다 → 해당 인원이 있을 때만 경고를 띄운다.

### 금액 표시 단위 · 동종업계

- **금액 표시 단위를 사용자 옵션으로** 구현(자동·원·천원·백만원·억원, 기본 **천원**). `workspace.amountUnit` 에 저장.
  저장·계산·엑셀·JSON 은 언제나 원 단위 정수이고 **표시 계층만** 바뀐다. 실무 확정(천원)을 옵션 형태로 반영한 것.
  - 표는 단위를 열 머리글로 올리고 칸에는 숫자만 둔다(`formatAmountBare`) — 결산서 관례이자 열 폭 절약.
  - 차트 축 눈금은 자릿수 때문에 자동 축약(억·만)을 유지한다.
  - **엑셀 입력 단위는 바꾸지 않는다.** 파일마다 단위가 달라지면 1000배 오류가 조용히 섞인다.
    바꾸려면 `조직 정보` 시트에 "금액 단위" 칸을 두어 파일이 자기 단위를 운반하게 할 것.
- **인건비 세부 항목 부분 입력 허용** — 세부 합계가 총액보다 적으면 경고만 내고 차액을 미분류로 둔다(실무 보유 항목 4개).
- **결산서 PDF 파싱 실측**: 텍스트 레이어는 있으나 DART 표는 라벨-숫자 정렬이 깨져 자동 파싱이 위험하다.
  → **동종업계 비교는 엑셀 수기 입력(8개사)으로 시작**하고, 반복이 확정되면 DART Open API 로 자동화한다. pdf.js 좌표 파싱은 채택하지 않음.
- 참고용 결산 PDF 는 `.gitignore` 로 제외(공개 저장소·대용량).

## 2026-09-03 — 인사담당자 확인 요청 회신 반영

18문항 질문지(공유 링크)에 대한 실무 담당자 답변으로 보류 중이던 결정 3건이 모두 확정됨.

- **분석 단위: 분기 필수, 월 선택** (4·8). 결산이 분기 단위이며 월별 결산을 준비 중. 연간 전용 데이터 모델을 기간 레코드로 확장해야 한다.
- **램프업·채용/퇴직 일회성 비용 미반영 확정** (17). 현재 시뮬레이션 모델을 그대로 유지한다.

  당장은 총액 중심으로 쓰고 세부는 나중에 채운다. 현재 엑셀 가져오기는 "세부 합계 ≠ 총액"을 오류로 막고 있어 **완화가 필요**하다.

  - 동종업계 결산 보고서를 올리면 **업계 평균**을 계산해 비교(14).
    둘 다 결산서 파싱을 전제한다. 다만 원본 PDF(18)라 텍스트 레이어가 있을 가능성이 높아,
    **이미지 OCR·서버 없이 브라우저에서 처리할 여지**가 있다 → 착수 전 실제 파일로 검증이 선행돼야 함.

## 2026-09-09 — 결산서 PDF → 엑셀 변환을 최우선으로, PDF 파싱 미채택 결정 철회

## 2026-09-09 — 결산서 PDF 가져오기 구현 결정 사항

- **받은 DART 반기보고서 2부를 기준 양식으로 착수**(사용자 결정). 담당자 자사 결산서는 배포 후 시험으로 확인. LLM 은 쓰지 않는다(규칙 기반이 결정적·무비용·외부 전송 없음).
- 기본값: **별도** 재무제표, 손익 **3개월** 열(반기보고서의 3개월 = 2분기, 누적 = 상반기 — 열을 바꾸면 기간도 바뀜), 인건비 = 성격별 비용의 급여·상여·퇴직급여·법정복리·복리후생·교육훈련 합(주식보상·장기종업원급여는 기본 제외, 포함 시 미분류로 총액에만 반영).
- 인원 = 직원 등 현황 **합계 행**(정규직·기간제·소속 외 구분 → `headcountBreakdown`, 총원은 산정 기준 적용). 합계 = 정규직 + 기간제 검산으로 열 위치를 확정한다. 기말 인원임을 항상 경고.
- 연결/별도 판별: 손익계산서는 제목, 주석 표는 **목차 쪽 범위 + 바닥글 Page N**. 판별 불가면 후보에 "?" 로 표시하고 사람이 고른다.
- 표가 쪽 끝에서 잘리면 다음 한 쪽을 이어 읽는다. 값은 표 단위 문구로 원 환산, 단위 문구가 없으면 원으로 가정하고 출처에 표시.
- 회사별 선택(연결/별도·열·항목)은 `workspace.pdfPrefs` 에 기억(localStorage·JSON 포함, 엑셀 `조직 정보` 시트에는 싣지 않음 — 앱 편의 설정이라서).
- 픽스처는 실 PDF 좌표에 **가상 수치**(4자리 이상 숫자 치환, 인원 같은 작은 수는 검산 유지를 위해 그대로) + 회사명 치환. 실 PDF 는 `probe.test.ts` 로 로컬에서만.
- 미구현으로 남긴 것: 수동 셀 지정 모드(내부 결산서 샘플 확보 후), 스캔 이미지 OCR.
