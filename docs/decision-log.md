# 결정 이력

## 2026-09-01 — 프로젝트 시작

- **별도 레포/폴더**로 진행 (`hcroi-simulator`). 개발자의 다른 프로젝트와 코드·DB 를 공유하지 않는다.
- 스택: SvelteKit(Svelte 5 runes) + TS + Tailwind v4 + vitest — 개발자가 이미 쓰는 스택과 통일.
- 프로토타입 저장소는 **localStorage**. DB 는 `hcroi` 전용 스키마 SQL 만 준비하고 어느 프로젝트에도 push 하지 않음
  (대상 Supabase 프로젝트 미정 · 추후 타 클라우드 이관 가능성).
- HCROI 1차 표기는 **배수**(요구사항의 "%"는 보조 표기). 1.3~1.5 구간은 "양호"로 정의(요구사항 미정의 구간).
- 시나리오의 비인건비는 **기본 고정비**로 가정, 변동비 비율은 고급 옵션으로 노출.
- 인원 변동 후 인당 인건비·인당 매출은 기준연도 값을 유지한다고 가정(램프업 미반영).
- 차트는 라이브러리 없이 인라인 SVG. 이중축 금지, 지표별 small multiple.
- 인사이트는 규칙 기반으로 시작. LLM 서술은 Phase 2.
- **DB 대상: 개발자 개인 Supabase 계정** 사용 (사용자 확정). 어느 프로젝트(기존 vs 신규)에 `hcroi` 스키마를 올릴지는
  DB 연동 착수 시 확정. 완성 후 회사 클라우드로 이관 예정이므로 `hcroi` 스키마 분리 원칙 유지.
- 이후 작업은 이 폴더에서 별도 Claude Code 세션으로 진행 (다른 프로젝트 세션과 분리).
- **git 기본 브랜치 `main`** (`master` 에서 변경). 커밋은 사용자 지시 시에만.
- 결정사항은 `.claude/brain.md`, 진행상황은 `.claude/state.md` 로 분리 관리. 이 파일은 시간순 이력 유지.
- 시뮬레이터 모델(변동비 기본 0%)은 유지하되, 개선 시나리오에서 매출 증가 + 변동비 0% 면 **과대 추정 경고 인사이트**를 띄운다
  (증원만으로 영업이익 ×2.7 이 나오는 샘플 케이스가 오해를 부를 수 있어서). 수치 모델 자체는 바꾸지 않음.
- HCROI 증감 표기는 "+0.34p" 대신 **"+0.34배"** (%p 와 혼동 방지).
- **엑셀 내보내기/가져오기를 다음 착수 항목으로 승격** (Phase 2 후보 → 계획 수립). 이유: 인사담당자가 JSON 을 다루기 어렵고 공유 표준이 엑셀.
  계획: docs/plans/excel-export-import.md (exceljs 권장, 클라이언트 처리, 지표는 값만 기록·가져오기 시 무시). 구현은 별도 지시 후.
- 전역 `cursor: pointer` 는 컴포넌트마다 클래스로 넣지 않고 `layout.css` `@layer base` 한 곳에서 처리.
- 엑셀 계획 확정 및 **구현 착수**: exceljs(MIT, 동적 import) / 금액 원 정수만(콤마 허용, 억 단위 불허) / 시나리오 시트는 내보내기 전용 / 조직명은 보류(회사별 사용 가능성 → 추후 조직 개념과 함께).
- 엑셀 내보내기/템플릿/가져오기 **구현 완료**. 가져오기는 항상 미리보기 → 반영, 반영 직전 스냅샷 1회 되돌리기. exceljs 는 `excel/io.ts` 에서만 동적 로드. JSON 은 "고급" 으로 격하.
- 데이터 관리 표: 행 클릭으로 연도 선택(엑셀처럼), 편집·삭제 버튼은 오른쪽 편집 패널로 이동 (사용자 요청).
- 시뮬레이터 슬라이더 범위를 **대칭**으로 (인원 ±30 · 임금 ±20 · 생산성 ±30 %). 0 이 정중앙에 오도록 — 사용자 지적.
- 데이터 관리 표: 행 끝 **휴지통 아이콘**으로 삭제(행 클릭 선택과 분리), 오른쪽 패널 버튼은 **초기화**(해당 연도 값을 표준 기본값으로, 매출액·인원 유지).
- 저장소: **개인 GitHub pulunick/hcroi-simulator, public** (사용자 결정. 공개 전 개인·회사 식별자 제거, 히스토리 단일 커밋으로 재생성). 첫 커밋 2026-09-01. 배포는 Vercel 로 인사담당자에게 링크 공유(2단계 시연 방식).
