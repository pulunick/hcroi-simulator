# HCROI & 인건비 시뮬레이터 — 요구사항 및 구현 명세

## 1. 배경

기업의 인적자본 투자효율성을 분석하고 미래 인건비·생산성을 시뮬레이션하는 사내 서비스.
인사담당자가 사용. 1차 목표는 **프로토타입** (계산 엔진 + 대시보드 + 시뮬레이터, 브라우저 저장).

## 2. 핵심 수식 (원문 그대로 — 모든 계산은 이 정의를 엄격히 따른다)

1. 인적자본 투입 전 이익 (Operating Profit before Human Capital)
   = 영업이익 + 총 인건비 = 매출액 − (영업비용 − 총 인건비)
2. HCROI = [매출액 − (영업비용 − 총 인건비)] ÷ 총 인건비 = (영업이익 + 총 인건비) ÷ 총 인건비
   — 인건비 1원 투입당 창출된 영업이익 + 인건비 회수율
3. HCVA = [매출액 − (영업비용 − 총 인건비)] ÷ 총 임직원 수
4. 총 인건비 = 기본급 + 성과급/수당 + 퇴직급여 + 법정후생비 + 기타 복리후생비 + 교육훈련비

구현: `src/lib/hcroi/formulas.ts` (`computeMetrics`, `sumHcCost`). 테스트: `formulas.test.ts`.

### 표기 규칙

- **분석 기간**은 연간(Y) · 반기(H) · 분기(Q) 중 하나이며 레코드마다 `period {year, type, index}` 로 식별한다(2026-09-08).
  - 값은 **그 기간의 실적 그대로** 저장·계산한다(연율화하지 않음). HCROI 는 같은 기간의 비율이라 기간 길이와 무관하고,
    HCVA·인당 지표·영업이익은 기간 금액이므로 화면에 "각 기간 실적 기준" 임을 밝힌다.
  - 결산이 없는 분기는 **반기 값을 반기 레코드로** 둔다. 분기로 나눠 추정하지 않는다.
  - 추이(차트·표·인사이트)의 **본체는 한 유형** — 분기와 연간 금액을 한 줄에 섞어 비교하지 않는다. 전기 = **달력상** 같은 유형의 바로 앞 기간(2025 Q1 → 2024 Q4)이며 그 기간이 없으면 비교하지 않는다(목록상 앞 레코드로 대신하지 않음). 반기·분기는 전년 동기도 함께 표기한다.
  - **추이 다개년 표시**(2026-09-10, `src/lib/hcroi/trend.ts`): 반기·분기·월 추이에서 그 유형 자료가 **하나도 없는 해**에 연간 레코드(직접 입력·합산)가 있으면 그 해는 연간 값을 **참조점**으로 같은 시간축에 올린다(속 빈 점·점선·"연간 참조" 표기). 참조점은 비율 지표인 HCROI 라인과 표에만 쓰고, 금액 누적 막대와 추이 인사이트는 본체 유형만 쓴다(기간 길이가 달라 금액 비교 불가). 그 해에 본체 유형이 하나라도 있으면 참조하지 않는다(연간을 쪼개 추정하지 않음).
    **표시 범위**는 "최근 N년"(마지막 자료 해 기준 달력 연도) 또는 전체이며 기본은 월 2년 · 분기 3년 · 반기 5년 · 연간 전체.
  - 정렬은 끝 월 기준: 한 해의 월·분기·반기 뒤에 연간(합계)이 온다. 라벨은 "2025년 3월 / 2025년 3분기 / 2025년 상반기 / 2025년".
  - **월(M)** 도 같은 구조다(2026-09-09). 순번 1–12, 엑셀 텍스트 "3월"(M3·3M 도 읽음), 전기 = 전월, 문구 "전월 대비 · N개월 연속".
  - **상위 기간은 저장하지 않고 읽을 때 합산한다**(`src/lib/hcroi/rollup.ts`, 2026-09-09). 월×3 → 분기, 분기×2 → 반기, 반기×2 → 연간.
    하위 기간이 **모두** 있을 때만 만들고(추정 금지), 직접 입력한 기간이 있으면 그것이 우선이며 합산과 다르면 항목별 차이를 경고한다.
    금액·인건비 세부는 합계, **임직원 수는 산정 방식**(기간 평균 → 하위 기간 평균 반올림, 기말 → 마지막 하위 기간)을 따른다.
    직접 입력한 상위 기간의 하위 기간이 하나만 비면 `상위 − 나머지 합` 으로 채운다(사업보고서의 4분기 = 연간 − 1~3분기).
    합산 레코드는 id `derived:<기간키>`, `derived {method, from, count}` 표시, 편집·삭제 불가("직접 입력으로 전환"으로 복사).
    **검증 오류(`validateRecord`)인 하위 기간은 "빠진 기간"과 똑같이 취급한다**(2026-09-15) — 그 기간이 든 상위 기간은 합산도 차감도 만들지 않고, 데이터 화면이 그 자리에 "합산 없음 — 하위 기간 오류(…)" 한 줄을 보여 준다. 오류 값을 뺀 채 조용히 작아진 합계가 지표·리포트로 나가지 않게 하기 위해서다(오류 레코드 자체는 저장·목록에 남는다).
- HCROI 는 **배수(1.35배)** 를 1차 표기로, 괄호에 % 환산(135%)을 보조 표기한다.
- **총 임직원 수는 산정 기준을 함께 표기한다.** 기본은 기간 평균(FTE) · 정규직만이며,
  계약직·기간제 / 파견·도급(소속 외) / 등기임원은 포함 여부를 고를 수 있다(기본 제외).
  인원 구분(정규직·계약직·파견·등기임원)을 입력한 연도의 총원은 이 기준으로 계산되고,
  기준은 작업공간 단위로 하나만 둔다 — 연도마다 다르면 추이 비교가 무의미해진다.
  (요구사항의 "HCROI(%)" 는 배수×100 으로 해석)
- 엑셀 `조직 정보` 시트가 **금액 단위**(원·천원·백만원)와 **손익 입력 방식**(기간 실적/누계)을 나른다(2026-09-09).
  가져오기가 단위를 곱하고, 누계면 같은 연도·유형 안에서 앞 순번을 빼 기간 실적으로 만든다(앞 순번 없으면 오류, 인원은 그대로). 내보내기는 원·기간 실적 고정.
  입력 시트에는 기간 드롭다운·셀 유효성·검증 열(수식)·조건부 서식·머리글 메모·시트 보호(비밀번호 없음)가 들어가지만 **규칙의 원본은 `validateRecord`** 다.
- 금액은 **원 단위 정수로 저장**하고 표시 단위만 사용자가 고른다 — 자동(억·만 축약) · 원 · 천원 · 백만원 · 억원.
  선택값은 작업공간(`amountUnit`)에 저장되고 계산·엑셀·JSON 의 값에는 영향을 주지 않는다.
  고정 단위를 고르면 표에서는 단위를 열 머리글로 올리고 칸에는 숫자만 둔다. 차트 축 눈금은 자릿수 때문에 자동 축약을 유지한다.

## 4. 시뮬레이터 모델링 가정 (`src/lib/hcroi/scenario.ts`)

입력 변수: 인원 변동율(%) 또는 변동 인원수(명), 평균 임금 인상률(%), 인당 생산성(인당 매출) 변화율(%),
[고급] 비인건비 중 변동비 비율(%, 기본 0).

1. 인원' = round(인원 × (1+변동율)) 또는 인원 ± N (최소 0)
2. 총 인건비' = 인원' × 인당 인건비 × (1 + 임금 인상률)
3. 매출액' = 인원' × 인당 매출 × (1 + 생산성 변화율)
4. 비인건비' = 고정비 + 변동비 × (매출액' ÷ 매출액) — 변동비 = 비인건비 × 변동비 비율
5. 영업비용' = 비인건비' + 총 인건비', 영업이익' = 매출액' − 영업비용'
6. HCROI'·HCVA' 는 핵심 수식으로 재계산

부가 산출(닫힌 식 역산, 테스트로 검증):

- 손익분기 생산성: HCROI' = HCROI(기준) 이 되는 생산성 변화율
- 최대 임금 인상률: 현 인원·생산성에서 HCROI 를 유지하는 임금 인상 상한

모델에 포함하지 않는 것: 신규 인원 램프업, 채용/퇴직 일회성 비용, 세금·금융비용.

## 5. 인사이트 규칙 (`src/lib/hcroi/insights.ts`)

- 시나리오 HCROI 악화 시: 헤드라인(등급 변동 포함) → 원인 분석(임금>생산성, 증원+생산성 정체, 감원+생산성 하락) →
  구조적 개선책(① 손익분기 생산성 ② 임금 인상 상한 ③ 필요 고정비 절감액 ④ 인력 구조 조정)
- 개선 시: 지속가능성 점검(감원 의존, 공격적 생산성 목표, 임금 삭감 부작용,
  매출이 기준 대비 1% 초과 증가 + 변동비 비율 0% 인 경우 "비인건비 전액 고정 가정에 의한 개선폭 과대 추정" 경고)
- HCROI 증감은 "+0.34배" 처럼 배 단위로 표기 (%p 와 혼동 방지)
- 영업손실 전환 시 critical 경고
- 연도 추이: N년 연속 하락, 전년 대비 변동, 인건비 증가율 vs 부가가치 증가율
- 항상 구체적 숫자와 단위(원, %, 명, 배)를 명시

Phase 2 에서 LLM(Claude API) 서술로 보강할 때 위 규칙과 산출치를 프롬프트 근거로 전달한다.

## 8. 저장소

- 프로토타입: localStorage (`hcroi:workspace:v1`). 가져오기 되돌리기용 스냅샷 `hcroi:workspace:v1:undo`
- 파일 교환: **엑셀(.xlsx)** 이 1차 — 내보내기(지표 요약·입력 데이터·시나리오 비교·조직 정보·산식 5시트), 템플릿, 가져오기(미리보기·검증·연도 병합·되돌리기).
  가져오기 대상은 `입력 데이터`(기간별 입력값 — `연도` + `기간` 열, 기간을 비우면 연간)와 `조직 정보`(회사/조직 이름 · 임직원 수 산정 기준) 두 시트뿐이고 지표 시트는 스냅샷(가져오기 시 무시) → 지표 미저장 원칙 유지.
  `조직 정보` 는 시트가 없으면 제목을 그대로 두고, 있으면 미리보기에서 사용자가 확인한 뒤 대시보드 제목에 반영한다. 구현 `src/lib/hcroi/excel/` (exceljs 동적 로드). JSON 은 고급 옵션으로 유지
- **결산서 PDF 가져오기** (2026-09-09, [계획](plans/pdf-to-excel.md)): 텍스트 PDF 를 브라우저 안에서 pdf.js 로 읽어(`src/lib/hcroi/pdf/`, `extract.ts` 만 동적 import) 표지·손익계산서·비용의 성격별 분류·직원 등 현황을 찾고,
  입력 칸별 후보 값(원 단위 환산, 출처 쪽·행·열)을 카드로 보여 준다. **사람이 확인한 뒤** 엑셀 가져오기와 같은 미리보기·병합·되돌리기 경로로 반영한다(자동 반영 없음). 회사명별 선택(연결/별도·3개월/누적·인건비 항목)은 `workspace.pdfPrefs` 에 기억한다.
  **기간은 표지에서 읽어 미리 채운다**(2026-09-15, `pdf/detectPeriod.ts`): 문서 종류가 유형을(사업보고서 Y · 반기보고서 H · 분기보고서 Q), 기간 문구의 **종료 월**이 순번을(03 Q1 · 06 H1/Q2 · 09 Q3 · 12 Y) 정하고 연도는 종료일 연도다.
  12월 결산이 아니거나 문구가 모자라면 같은 값을 제안하되 `확인 필요`(low) 로 표시하고, 아예 못 읽으면 기간 셀렉트를 비워 두고 고르기 전에는 미리보기로 보낼 수 없다. 규칙표는 [계획 §5.1](plans/pdf-to-excel.md).
  스캔 이미지(OCR)·내부 결산서 전용 수동 셀 지정은 Phase 2
