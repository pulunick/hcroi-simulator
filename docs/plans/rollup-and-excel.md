# 기간 합산(월→분기→연간) · 엑셀 작성 편의 — 계획 (2026-09-09)

> 상태: **완료(2026-09-09, 커밋 91dfabe)**. 담당자 2차 확인 전에 넣었다. 결정: 2026-09-09 사용자 승인(직접 입력 우선 · 산정 방식이 합산 규칙이 됨).

## 왜

- 분기 4개를 넣어도 연간이 안 나오고, 연간을 따로 넣으면 둘이 달라도 경고가 없다(9/8 기간 레코드 전환 때 합산 규칙을 두지 않았다).
- 결산서는 천원 단위·누계로 나오고 사업보고서에는 4분기 값이 없다. 템플릿은 원 단위·기간 실적만 받아 손이 많이 간다.
- 엑셀에서 틀린 것을 앱에 올려 봐야 안다.

## 규칙

1. **월(M) 유형 추가.** `period.type: 'Y'|'H'|'Q'|'M'`, 순번 1–12. 라벨 "2025년 3월", 짧게 "2025.03", 엑셀 텍스트 "3월"(M3·3M 도 읽음). 전기 = 전월, 전년 동기 = 작년 같은 달. 문구는 "전월 대비 · N개월 연속".
2. **가장 잘게 넣은 값만 저장하고 상위 기간은 읽을 때 계산한다**(`src/lib/hcroi/rollup.ts`). 계산된 레코드는 저장하지 않는다(지표 미저장 원칙과 같은 선).
   - 사슬: M×3 → Q, Q×2 → H, H×2 → Y. 중간이 직접 입력이면 그것을 쓴다(직접 입력 우선).
   - 하위 기간이 **모두** 있을 때만 만든다. 1~3분기만 있으면 연간은 만들지 않는다(추정 금지).
   - 매출·영업비용·인건비·인건비 세부 = 합계. **임직원 수 = 산정 방식**을 따른다: 기간 평균 → 하위 기간 평균(반올림), 기말 → 마지막 하위 기간 값. 인원 구분도 같은 규칙. 하위 기간 중 하나라도 세부/구분이 없으면 상위는 null.
   - 산정 방식(기간 평균/기말)은 이제 **표기용이 아니라 합산 규칙**이다(brain §11 갱신).
3. **차감 도출**: 직접 입력한 상위 기간이 있고 하위 기간이 **하나만** 비면 그 하나를 `상위 − 나머지 합` 으로 만든다(사업보고서의 4분기 = 연간 − 1~3분기 누계). 결과가 검증(`validateInputs`)을 통과할 때만. 인원은 기간 평균이면 `n×상위 − Σ나머지`(1 미만이면 상위 값), 기말이면 상위 값.
4. **직접 입력과 합산이 다르면 경고**(값은 직접 입력 우선). 대시보드·데이터 관리에서 항목별 차이를 보여 준다.
5. 화면: 조회 기간·기준 기간·추이·표에 합산 레코드가 `합산` 표시와 함께 들어간다. 합산 레코드는 편집·삭제 불가, "직접 입력으로 전환" 으로 복사본을 만들 수 있다.
6. 엑셀
   - `조직 정보` 시트에 **금액 단위**(원/천원/백만원, 드롭다운)와 **손익 입력 방식**(기간 실적/누계) 칸. 가져오기가 단위를 곱하고, 누계면 같은 연도·유형 안에서 `순번 i − 순번 i−1` 로 기간 값을 만든다(앞 순번이 빠지면 오류). 인원은 누계 대상이 아니다. 내보내기는 원 단위·기간 실적 고정.
   - `입력 데이터`: 기간 열 드롭다운(연간·상반기·하반기·1~~4분기·1~~12월), 연도·금액·인원 셀 유효성, 행 끝 **검증** 열(수식: 필수 누락 · 세부 합계>총액 · 총원≠구분 합계 · 인건비>영업비용)과 조건부 서식(붉은 행), 머리글 메모, 시트 보호(비밀번호 없음, 입력 칸만 열림). 검증 열은 가져오기가 읽지 않는다.
   - 앱의 `validateRecord` 가 규칙의 원본. 엑셀 검증은 안내용(붙여넣기로 뚫린다).
7. 샘플: 2025년 연간 레코드를 빼고 분기 4개만 둔다(연간이 합산으로 나오는 것을 보여 준다).

## 미루는 것

- 세로형(행=기간) 템플릿 유지. 가로형은 담당자 결산 시트 모양을 본 뒤 결정(시연 질문).
- 월 추이 차트의 36점 밀집은 일단 그대로. 필요하면 라벨 간격 조정.
