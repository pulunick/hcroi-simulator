# 결산서 PDF → 엑셀 입력 시트 자동 변환 — 기획설계

> 작성 2026-09-09. 상태: **M1–M4 구현 완료(2026-09-09), 문서 반영 완료**. 남은 것: §6 수동 셀 지정 모드(내부 결산서 샘플을 받은 뒤), 담당자 자사 결산서로 실전 검증.
> 구현: `src/lib/hcroi/pdf/`(types · table · locate · map · toRecord · extract) + `src/lib/components/data/PdfImport.svelte` + `/data` 연결. 테스트 `pdf/table.test.ts`·`locate.test.ts`(픽스처 = 실 좌표 + 가상 수치), 실 PDF 는 `probe.test.ts`(`HCROI_PDF=` 로컬 전용).
> 배경: 인사담당자와의 논의에서 **"PDF 로 받은 결산서를 우리 엑셀 양식에 옮겨 적는 수고를 없애는 것"** 이 가장 중요한 요구로 확인됐다(부서별·동종업계보다 우선).
> 이 문서는 2026-09-08 의 "PDF 파싱은 채택하지 않는다" 결정을 실측으로 뒤집고, 무엇을 어떻게 만들지 정한다. 구현되면 spec §8 · user-guide §8 로 흡수한다.

## 0. 한 줄 요약

브라우저 안에서 PDF 의 텍스트 좌표를 읽어 표를 복원하고, 결산서의 4개 값(매출액 · 영업이익/영업비용 · 총 인건비 · 총 임직원 수)과 인건비 세부·인원 구분을 **후보로 찾아 보여 주면 사람이 확인**한 뒤, 기존 엑셀 가져오기와 같은 경로로 앱에 반영하거나 `입력 데이터` 시트가 채워진 엑셀 파일로 내려받는다. 서버·외부 전송 없음. 100% 자동이 아니라 **"옮겨 적기"를 "확인하기"로 바꾸는 것**이 목표다.

## 1. 왜 지금 가능하다고 보는가 (2026-09-09 실측)

2026-09-08 의 부정적 결론은 `pdftotext -layout` 출력 기준이었다. 오늘 `pdftotext -table` 과 **pdf.js 좌표 추출**(브라우저에서 쓸 바로 그 라이브러리, `pdfjs-dist 4.10`)로 같은 두 반기보고서를 다시 읽었다.

| 표                 | 루닛(별도, 단위 원·천원·백만원 혼재)                                    | 코어라인소프트(별도)                                            | 판정                        |
| ------------------ | ----------------------------------------------------------------------- | --------------------------------------------------------------- | --------------------------- |
| 포괄손익계산서     | 영업수익·영업비용·영업손실 4열(3개월/누적 × 당기/전기) 모두 제자리      | 동일. 괄호 음수도 셀 단위로 분리됨                              | ✅ 좌표로 복원              |
| 비용의 성격별 분류 | "당기손익에 포함되는 퇴직급여" 라벨이 2줄이라 **숫자가 다음 행에 붙음** | 종업원급여·복리후생비 등 제자리                                 | ✅ 다줄 라벨 병합 규칙 필요 |
| 직원 등 현황       | 합계 행: 243명 / 11,559 백만원 제자리. 헤더는 3줄로 흩어짐              | 합계 행: 95명 / 3,207,410 천원. "합 계" 처럼 **글자 사이 공백** | ✅ 합계 행만 쓰면 안정      |
| 요약재무정보       | 3열(반기·전기·전전기)로 제자리 — 이전 "어긋남"은 `-layout` 줄 접합 문제 | —                                                               | 참고용(쓰지 않음)           |

즉 **표 복원 자체는 문제가 아니다.** 남는 어려움은 ① 수백 쪽 중 어느 표를 쓸지 찾기 ② 회사마다 다른 계정명 ③ 단위·3개월/누적·연결/별도 ④ 내부 결산서(비 DART) 양식 미확인 — 전부 규칙 + 사용자 확인으로 다룰 수 있는 종류다.

스파이크 스크립트는 스크래치패드 `spike.mjs`(pdf.js `getTextContent` → y 클러스터 → x 정렬 → 인접 조각 병합). 이 로직이 §4 `table.ts` 의 출발점이다.

## 2. 사용자 흐름

데이터 관리(`/data`) 의 엑셀 가져오기 옆에 **"결산서 PDF 에서 가져오기"** 를 둔다.

1. **파일 선택** — PDF 여러 개 가능(분기마다 한 부). 텍스트 레이어가 없으면 즉시 안내("스캔 이미지라 읽을 수 없습니다 → 엑셀 템플릿에 수기 입력").
2. **인식 결과 카드** (파일마다 1장)
   - 상단: 감지한 **기간**(표지 "2026.01.01 부터 2026.06.30 까지" → 2026 상반기) · **회사명** · **단위** · **연결/별도** 선택(기본 별도).
   - 본문: 입력 칸마다 한 줄 — `찾은 값` · `출처(쪽 · 표 이름 · 행 라벨 · 열)` · `원문 행 보기` · `다른 후보 ▾` · `직접 입력`.
     - 매출액 / 영업비용 또는 영업이익 / 총 인건비(구성 항목 체크리스트: 급여 ☑ 퇴직급여 ☑ 복리후생비 ☑ 주식보상비용 ☐ …) / 총 임직원 수(정규직·기간제·소속 외 근로자 구분 포함)
   - 하단: 자동 검증 — `매출 − 영업비용 = 영업이익` · `세부 합계 ≤ 총 인건비` · `직원 현황 연간급여총액 vs 총 인건비 비율`(크게 다르면 경고) · `기말 인원인데 산정 기준은 기간 평균` 경고.
3. **반영** — 확인한 값이 `Omit<PeriodRecord,'id'>` 가 되어 **기존 엑셀 가져오기 미리보기**(신규/덮어씀/오류 · 되돌리기)로 합류한다. 같은 자리에 **"엑셀로 저장"** 버튼: 현재 작업공간 + 새 레코드를 `buildWorkbookBuffer` 로 내려받는다(담당자가 원한 "엑셀 양식으로 맞추기").
4. **기억** — 카드에서 고른 계정명·항목 구성·연결/별도·열(3개월/누적)은 회사명 단위로 `workspace.pdfMappings` 에 저장돼 **다음 분기부터 자동 적용**된다. 엑셀 `조직 정보` 시트로도 내보내지 않는다(앱 내부 편의 설정, JSON 내보내기에는 포함).

원칙: **자동으로 값을 반영하지 않는다.** 항상 카드에서 출처를 보고 확인한다. 신뢰도가 낮은 칸(후보 2개 이상, 검증식 불일치)은 노란색으로 표시하고 확인 전엔 반영 버튼을 막는다.

## 3. 범위

**포함**

- 텍스트 레이어가 있는 PDF: DART 분기·반기·사업보고서, 감사보고서, 회계팀 내부 결산서(텍스트 PDF)
- 값: 매출액, 영업비용/영업이익, 총 인건비 + 세부(찾히는 항목만: 급여→기본급, 퇴직급여, 복리후생비→기타 복리후생비, 교육훈련비, 법정복리후생비), 총 임직원 수 + 구분(기간제→계약직, 소속 외 근로자→파견)
- 기간 자동 감지(연·반기·분기), 단위 자동 감지, 누계→기간 실적 변환(기존 `cumulative` 옵션 재사용)
- 여러 파일 일괄, 매핑 기억, 수동 셀 지정(§6)

**제외 (Phase 2)**

- 이미지 스캔 OCR(tesseract.js 검토 대상. 담당자가 실제로 스캔본을 받는 경우가 생기면)
- 동종업계 보고서 일괄 → 평균 (같은 파이프라인으로 확장 가능하지만 `동종업계` 시트 설계가 먼저)
- 변동비 비율 추출(변동비 정의가 미확정 — review-2 §3)
- 부서별 인건비 (결산서에 없음)

## 4. 아키텍처

새 모듈 `src/lib/hcroi/pdf/` — exceljs 와 같은 원칙으로 **pdf.js 는 `extract.ts` 에서만 동적 import**, 나머지는 순수 함수라 vitest 로 검증한다.

```
extract.ts   pdf.js 동적 import. File → PageText[] { page, width, height, items: TextItem[] }
             TextItem = { s, x, y, w, h }  (getTextContent 의 transform[4], [5], width, height)
             worker 는 `pdfjs-dist/build/pdf.worker.min.mjs?url` 정적 자산. 텍스트 없는 PDF 감지(items 0 → 오류)
table.ts     순수. TextItem[] → Row[] → Table[]
             ① y 허용치(±2.5pt)로 행 묶기 ② x 정렬 ③ 인접 조각 병합(gap < 3pt, 한글 글자 띄어쓰기 "합 계" 는 라벨 위치면 공백 제거 비교)
             ④ 숫자 셀 파싱: 콤마, 괄호·△·- 음수, "-" 단독 = 0/없음 ⑤ 숫자 없는 행(라벨만)이 바로 아래 숫자만 있는 행과 붙으면 한 행으로(다줄 라벨)
             ⑥ 헤더 행(숫자 없음, "3개월/누적/당기/전기/제 N 기") 과 단위 행 "(단위 : X)" 인식 → Table { page, title, unitScale, columns[], rows[{label, values[]}] }
locate.ts    순수. Table[] → 후보 표 { kind: 'pl' | 'expenseByNature' | 'employees' | 'cover', consolidated: boolean, ... }
             앵커: 손익계산서("포괄손익계산서"·"손익계산서" 제목 + 매출 동의어 행), 성격별("성격별"), 직원("직원 등 현황"·"직원 등의 현황"), 표지(기간 문구)
             연결/별도: 표 제목·바로 위 제목에 "연결" 포함 여부, DART 목차 번호(2-x 연결 / 4-x 별도)
map.ts       순수. 후보 표 + 계정 사전 → 입력 칸별 후보 { key, value, source: {page, table, rowLabel, column}, confidence }
             사전은 정규식 배열(동의어): 매출액|영업수익|수익\(매출액\)|매출 / 영업이익|영업이익\(손실\)|영업손실 / 급여|종업원급여|단기종업원급여|임금|급료 …
             회사별 기억(`PdfMapping`)이 있으면 사전보다 우선
toRecord.ts  순수. 확인된 후보 → Omit<PeriodRecord,'id'> + warnings. 단위 배수·누계 차감은 기존 fromRows 의 규칙을 재사용(함수 추출 필요)
             이후는 기존 `validateRecord` → `mergeRecords` 그대로
```

상태: `workspace.pdfMappings: Record<orgName, PdfMapping>` (계정 선택·항목 구성·연결/별도·열). 지표는 여전히 저장하지 않고, PDF 원문 텍스트도 저장하지 않는다(추출 값만).

번들: `pdfjs-dist` 본체 ~350KB + worker ~1.3MB(둘 다 gzip 전). 동적 import 라 PDF 버튼을 누르기 전엔 로드되지 않는다. Vercel 정적 자산으로 문제 없음.

## 5. 추출 규칙 (표별)

### 5.1 표지 → 기간 · 회사명 · 보고서 종류

**기간 감지 규칙** (2026-09-15 구현, `pdf/detectPeriod.ts` — 순수 함수, 테스트 `detectPeriod.test.ts`).
앞 8쪽만 본다(뒤쪽 재무제표 머리글에도 같은 문구가 있어 멀리 가면 틀린다). 쪽의 조각을 읽는 순서로 이어 붙이고 공백을 지운 뒤 찾는다 — DART 표지는 "…까지" 와 "…부터" 가 **서로 다른 줄**에 있어 줄 단위로는 범위를 못 읽는다.

| 읽는 문구                                                                                      | 쓰는 곳                                                       |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `사업보고서` / `반기보고서` / `분기보고서` (글자 사이 공백 무관)                               | **기간 유형** Y / H / Q                                       |
| `YYYY년 MM월 DD일 부터 … 까지` · `YYYY.MM.DD ~ YYYY.MM.DD` · `YYYY-MM-DD ~ …` (`/` · 붙임표도) | **종료일** → 연도(종료일 연도)와 순번                         |
| `제 N 기`                                                                                      | 근거 문구에만. 결산월이 회사마다 달라 순번 계산에 쓰지 않는다 |

| 종료 월 | 사업보고서 | 반기보고서 | 분기보고서                                |
| ------- | ---------- | ---------- | ----------------------------------------- |
| 03      | 연간       | 상반기     | **1분기**                                 |
| 06      | 연간       | **상반기** | **2분기**                                 |
| 09      | 연간       | 하반기     | **3분기** (누적 01.01~09.30 이어도 3분기) |
| 12      | **연간**   | 하반기     | 4분기                                     |

- 신뢰도: 12월 결산 + 종료 월이 기간 끝에 맞으면 `high`. 그 밖(3월 결산처럼 종료일 연도·시작 월이 어긋남 · 종류 문구만 있고 기간 문구가 없어 가장 최근 4자리 연도로 추정 · 종류 문구 없이 기간 폭으로 유형 추정)은 **같은 값을 제안하되 `low`** → 화면에 `확인 필요`.
- 아무것도 못 찾으면 `null` — 화면은 기간 셀렉트를 **빈 값("기간을 고르세요")** 으로 두고, 고르기 전에는 미리보기로 보낼 수 없다.
- 손익 열로 `3개월` 을 고르면 반기 감지는 그 반기의 끝 분기로 옮긴다(상반기 → 2분기, `periodForThreeMonthColumn`). 거꾸로 **반기보고서를 감지하면 열 기본값이 `누적`** 이 되어 라벨과 값이 어긋나지 않는다(회사별 기억값이 있으면 기억값이 열을 정한다).
- `workspace.pdfPrefs` 는 기간을 기억하지 않는다(연결/별도 · 열 · 인건비 항목만) — 기간은 언제나 파일에서 다시 읽는다.

기존(2026-09-09) 표지 스캔 `locate.scanCover` + `map.periodForColumn` 은 감지가 실패했을 때의 폴백으로 남는다:

- `제 N 기 (반기|분기)? YYYY.MM.DD 부터 YYYY.MM.DD 까지` → 시작·끝 월로 `Period` 결정: 1–12 → Y, 1–6 → H1, 7–12 → H2, 3개월 폭 → Q. **DART 분기보고서(3분기)는 누적 1–9월** 이므로 표에서 "3개월" 열을 고르면 Q3, "누적" 열을 고르면 기존 `cumulative` 로 차감.
- 회사명: 표지 "회사명 : ○○" 또는 첫 쪽 상단. 실패 시 사용자가 입력(기억 키가 되므로 필수).
- 사업보고서(연간)는 손익 표에 3개월 열이 없다 → Y 레코드.

### 5.2 손익계산서 → 매출액 · 영업비용 · 영업이익

- 후보 표 중 **별도** 우선(옵션으로 연결). 두 표가 다 있고 사용자가 고르지 않았으면 카드에 "연결/별도" 토글을 강조.
- 열: 당기 그룹의 첫 열(3개월) 또는 둘째 열(누적). 기본 = 분기 파일이면 3개월, 반기·연간이면 누적/당기.
- 행: 매출 동의어 첫 일치, 영업비용(있으면), 영업이익 동의어. 영업비용이 없고 `매출원가` + `판매비와관리비` 가 있으면 합으로 영업비용을 만든다(출처 두 행 표기).
- 검증: `매출 − 영업비용 = 영업이익` (±1원). 불일치면 둘 다 후보로 두고 경고.

### 5.3 비용의 성격별 분류 → 총 인건비 · 세부

- 행 → 항목: 급여·종업원급여·단기종업원급여 → **기본급**(성과급이 섞여 있을 수 있음을 힌트로 표시) / 퇴직급여 → 퇴직급여 / 복리후생비 → 기타 복리후생비 / 법정복리후생비·4대보험 → 법정후생비 / 교육훈련비 → 교육훈련비.
- 기본 제외: 주식보상비용, 장기종업원급여(기타장기) — 카드 체크리스트로 포함 가능.
- 총 인건비 = 체크된 행의 합. 세부는 매핑된 항목만 채우고 나머지는 null(현재 "부분 입력 허용" 규칙 그대로).
- 표가 없는 회사(성격별 공시를 안 하는 경우) → 판관비 명세 표(`판매비와관리비`) 로 폴백하되 "매출원가 인건비 누락 가능" 경고.

### 5.4 직원 등 현황 → 총 임직원 수 · 구분

- **합계 행**만 쓴다(부문·성별 행은 무시). 열은 헤더 3줄을 합쳐 판별: `기간의 정함이 없는 근로자 합계` → 정규직, `기간제 근로자 합계` → 계약직, `소속 외 근로자 계` → 파견, `직원수 합계` → 총원 후보, `연간급여 총액` → 교차검증용.
- 헤더 병합이 실패하면 열 순서 기본값(DART 표준 순서)을 쓰고 "열 위치 추정" 경고.
- 기말 인원임을 항상 표시. 산정 기준이 기간 평균이면 "인사 시스템 평균 인원으로 바꿔 넣으세요" 힌트.
- 연간급여총액(단위 별도)과 총 인건비를 비교해 2배 이상 차이 나면 경고(단위 오판 감지).

### 5.5 단위

- 표마다 가장 가까운 위쪽의 `(단위 : 원|천원|백만원)` 을 쓴다. 표 안에 단위가 다른 열(직원 현황의 급여액)이 있으면 헤더 문구를 우선.
- 값은 언제나 **원 단위 정수**로 환산해 레코드에 넣는다(엑셀 가져오기와 동일 원칙).

## 6. DART 가 아닌 내부 결산서

양식을 아직 못 봤다. 대응 순서:

1. §4 파이프라인은 양식 무관(표 복원 + 계정 사전)이라 텍스트 PDF 면 우선 그대로 시도한다.
2. **수동 셀 지정 모드**: 쪽 번호로 이동 → 복원된 표를 화면에 그리고 → 셀을 클릭해 입력 칸에 넣는다. 한 번 지정하면 `PdfMapping` 에 (쪽 앵커 문구 · 행 라벨 · 열 순번)으로 저장돼 다음 파일에 재적용.
3. 회계팀이 엑셀에서 PDF 로 찍은 파일이면 텍스트 레이어가 있고 표가 단정해 1번으로 끝날 가능성이 높다.

→ 착수 전에 **샘플 1부(수치 가려도 됨)** 가 필요하다. §9 확인 사항 1.

## 9. 사용자에게 확인할 것 (M3 전)

1. **실제로 받는 PDF 가 무엇인가** — DART 보고서인가, 회계팀 내부 결산서(어떤 프로그램에서 찍은 것)인가. 가능하면 샘플 1부(수치 가려도 됨). 비상장사면 DART 가 없으므로 이 답이 설계의 절반을 정한다.
2. 연결 / 별도 중 어느 재무제표를 기준으로 쓰는가. (기본 별도로 잡았다 — 인원이 본사 기준이라서)
3. 분기 값은 손익계산서의 "3개월" 열인가, 누계 열을 옮겨 적고 있었나. (둘 다 지원, 기본값만 정하면 됨)
4. 인건비로 보는 성격별 비용 행: 급여·퇴직급여·복리후생비 외에 주식보상비용·장기종업원급여를 넣는가.
5. 임직원 수는 직원 등 현황의 기말 합계로 충분한가, 아니면 인사 시스템 평균 인원을 따로 넣는가.
6. 결과를 **앱에 바로 반영**하는 것과 **엑셀 파일로 받는 것** 중 어느 쪽이 기본 동작이어야 하는가. (둘 다 제공)
