# 계획 — 엑셀 내보내기 / 가져오기

작성 2026-09-01. 상태: **구현 완료 (2026-09-01)** — A·B·C·D 모두 반영. 이 문서는 설계 기록으로 유지하며 사용법은 [user-guide.md §4](../user-guide.md), 저장 방식은 [spec.md §8](../spec.md).

**§9 확정 (2026-09-01)**: ① exceljs 채택 ② 금액은 원 단위 정수만(콤마 문자열은 허용, 억 단위 미허용) ③ 시나리오는 내보내기만 ④ 헤더명은 §3 안 ⑤ 조직명은 보류 — 현재 단일 회사지만 회사별 사용 가능성이 있어 파일명·시트에 회사명을 박지 않고, 추후 조직 개념 도입 시 연결.

## 1. 왜

- 사용자는 인사담당자. **JSON 은 열어볼 수도, 고칠 수도 없다.** 현재 유일한 백업·공유 수단이 JSON 이라 실사용에 벽이 된다.
- 회의·보고 공유는 엑셀이 표준. 지표 표를 그대로 붙일 수 있어야 한다.
- 재무팀이 이미 엑셀로 가진 연도별 매출·비용·인건비를 **손으로 다시 치지 않고** 올릴 수 있어야 한다.

## 2. 범위

| 기능                   | 내용                                                                                            | 우선순위      |
| ---------------------- | ----------------------------------------------------------------------------------------------- | ------------- |
| **A. 엑셀 내보내기**   | 현재 작업공간을 `.xlsx` 1개 파일로. 시트: ① 지표 요약 ② 입력 데이터 ③ 시나리오 비교 ④ 산식·가정 | 1 (먼저)      |
| **B. 템플릿 다운로드** | 비어 있는(또는 샘플 채워진) 입력 시트. 헤더·단위·예시 행·주석 포함                              | 1             |
| **C. 엑셀 가져오기**   | 템플릿(또는 내보낸 파일의 ② 시트)을 업로드 → 미리보기·검증 → 반영                               | 2             |
| D. JSON 격하           | JSON 내보내기/가져오기는 유지하되 "고급" 으로 접어 넣기                                         | 3 (C 완료 후) |

범위 밖: 서버 업로드(클라이언트에서만 처리), 엑셀 수식으로 지표 재계산(값만 기록), 부서별 시트.

## 3. 파일 설계

### 시트 ① `지표 요약` (읽기 전용 스냅샷)

연도 | HCROI(배) | HCROI(%) | 등급 | HCVA(원/인) | 매출액(원) | 영업이익(원) | 총 인건비(원) | 총 임직원 수(명) | 인당 매출(원/인) | 인당 인건비(원/인) | 영업이익률(%) | 매출 대비 인건비율(%)

- 첫 행 위에 안내: "이 시트는 계산 결과 스냅샷입니다. 가져오기 시 무시됩니다. 입력은 `입력 데이터` 시트를 고치세요."
- 숫자 서식: 배수 `0.00"배"`, 금액 `#,##0`, 비율 `0.0"%"`. 열 너비 고정. 헤더 굵게·배경.

### 시트 ② `입력 데이터` (= 템플릿과 동일 구조, 왕복 가능)

연도\* | 매출액(원)\* | 영업비용(원, 인건비 포함) | 영업이익(원) | 총 임직원 수(명)\* | 총 인건비(원)\* | 기본급 | 성과급/수당 | 퇴직급여 | 법정후생비 | 기타 복리후생비 | 교육훈련비 | 메모

- `*` 필수. **영업비용 또는 영업이익 중 하나**만 있으면 됨(둘 다 있으면 영업비용 우선, 불일치 시 경고).
- 인건비 6항목은 선택. 있으면 합계 = 총 인건비 검증(±1원). 비어 있으면 총액만 저장(`breakdown: null`).
- 금액은 **원 단위 정수**. 셀에 `14,100,000,000` 문자열이 와도 콤마 제거 후 파싱. "억" 단위 입력은 받지 않음(헤더에 명시) — _사용자 확인 필요_.
- 2행에 단위/설명 행(회색), 3행부터 데이터. 가져오기는 2행을 건너뛴다.

### 시트 ③ `시나리오 비교` (읽기 전용)

기준연도, 시나리오 A/B 파라미터(인원 변동·임금 인상률·생산성 변화율·변동비 비율) + 현재 `/simulator` 비교표 9지표 (기준/A/B/증감). 가져오기 대상 아님 — _시나리오 파라미터도 가져오기 대상으로 할지 사용자 확인 필요_.

### 시트 ④ `산식·가정`

spec §2~§4 텍스트. 파일만 받은 사람도 숫자 뜻을 알 수 있게.

파일명: `hcroi-<조직명 또는 workspace>-YYYY-MM-DD.xlsx`.

## 4. 가져오기 UX (`/data`)

1. `엑셀 가져오기` 클릭 → 파일 선택(.xlsx). (템플릿 다운로드 버튼을 바로 옆에)
2. 파싱 → **미리보기 표**: 행별 상태(신규 / 기존 연도 덮어씀 / 오류) + 오류 메시지(필수값 누락, 음수, 인건비 > 영업비용, 세부 합계 불일치, 연도 중복).
3. 옵션: `기존 연도 덮어쓰기` (기본 켬) / `오류 행 건너뛰고 나머지만 반영`.
4. `반영` → workspace 갱신 → 자동 저장. 반영 전 상태는 **자동 JSON 스냅샷**으로 localStorage 에 1개 보관(되돌리기 1회).
5. 오류가 하나라도 있고 "건너뛰기" 를 안 켰으면 반영 버튼 비활성.

## 5. 기술 선택

| 후보              | 장점                                                                   | 단점                                                                            | 판단                                 |
| ----------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------ |
| **exceljs** (MIT) | 셀 서식·열 너비·주석 지원(공유용 품질↑), 읽기/쓰기 모두, 브라우저 동작 | 번들 큼(~900KB) → **클릭 시 동적 import** 로 해결                               | **권장**                             |
| SheetJS CE `xlsx` | 가볍고 빠름                                                            | npm 배포판이 구버전(0.18.5)이고 서식은 Pro 유료. 최신판은 자체 CDN tarball 설치 | 비권장                               |
| CSV(+BOM)         | 의존성 0                                                               | 시트 1개, 서식 없음, 한글 깨짐 이슈                                             | 보조 수단으로만 (지표 요약 CSV 복사) |

- 처리는 **전부 브라우저**에서(vercel 어댑터·localStorage 구조 그대로). 서버 라우트 불필요.
- 다운로드는 Blob + `<a download>` (JSON 내보내기와 동일 패턴).

## 6. 코드 구조 (계산 소스 단일 원칙 유지)

```
src/lib/hcroi/excel/
  schema.ts      시트·열 정의 (헤더 문자열, 필수 여부, 단위) — 내보내기/템플릿/가져오기가 같은 정의를 씀
  toRows.ts      YearRecord[] → 시트 ② 행 / Metrics → 시트 ① 행 / ScenarioResult → 시트 ③ 행   (순수 함수, 테스트)
  fromRows.ts    시트 ② 행(unknown[][]) → { records: YearRecord[], errors: RowError[] }        (순수 함수, 테스트)
  io.ts          exceljs 로 Workbook 만들기/읽기 (동적 import). 위 순수 함수만 호출
src/routes/data/+page.svelte   버튼 3개(엑셀 내보내기·템플릿·가져오기) + 미리보기 모달
```

- 지표는 `computeMetrics` 로 내보내기 시점에 계산해 **값만 기록**. 가져오기는 시트 ①③ 을 읽지 않는다 → "지표 저장 금지" 규칙 유지.
- 검증은 기존 `validateInputs` + `sumHcCost` 재사용.

## 7. 테스트

- `fromRows` : 정상 행, 콤마 문자열, 영업이익만 있는 행, 세부 합계 불일치, 필수 누락, 연도 중복, 빈 행 무시.
- `toRows` → `fromRows` 왕복: 샘플 3개년이 그대로 복원되는지(id 는 연도 매칭으로 유지).
- `io.ts` : exceljs 로 쓰고 다시 읽는 통합 테스트 1개 (node 환경, vitest).
- UI 는 Playwright 수동 점검(파일 선택 → 미리보기 → 반영).

## 9. 착수 전 사용자 확인 사항

1. **exceljs 채택** 동의 여부 (번들 크기 vs 서식 품질).
2. 금액 단위: 원 정수만 받을지, "억원" 소수 입력도 허용할지(허용 시 반올림 규칙 필요).
3. 시나리오 파라미터도 가져오기 대상인지 (기본: 내보내기만).
4. 시트/헤더 이름 한국어 확정안(위 §3) 검토.
5. 내보내기에 회사명(조직명) 입력칸을 둘지 — 현재 작업공간에 조직 개념이 없음.
